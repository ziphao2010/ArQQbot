# QQ 机器人触发条件与使用场景分析

- 日期：2026-11-01
- 适用版本：ArQQbot 第一阶段
- 参考：QQ 机器人官方文档（事件订阅、消息收发、接口鉴权）

## 1. 机器人什么时候会被调用

QQ 官方机器人是**事件驱动**的：只有平台把事件推送到已连接网关，插件才会被调用。满足以下全部条件时，事件才会到达：

1. 机器人实例已启动，网关状态为 READY（日志出现“QQ 网关已就绪”）。
2. AppID / AppSecret 有效，access_token 获取成功。
3. 机器人已被加入对应群，或用户已能与机器人单聊。
4. 当前实例环境与场景匹配：
   - 沙箱实例只接收沙箱测试群/测试成员的事件。
   - 正式实例只接收正式环境、已发布功能对应的事件。
5. 事件类型已包含在订阅的 intents 中（当前实现订阅 `PUBLIC_MESSAGES`，即 `1 << 25`）。
6. 触发动作符合平台规则，例如群聊必须直接 @ 机器人，而不是发送普通群消息或 @全体成员。

### 1.1 各场景触发条件

| 场景 | 事件 | 触发条件 | 当前实现 |
| --- | --- | --- | --- |
| 群聊 @ 机器人 | `GROUP_AT_MESSAGE_CREATE` | 用户在机器人所在群内直接 @ 机器人发送消息；沙箱仅测试群生效 | 已支持 |
| 群聊全量消息 | `GROUP_MESSAGE_CREATE` | 群主/管理员允许机器人接收群内全部消息 | 未处理（适配器会记录“暂未处理的 QQ 事件”） |
| 单聊 | `C2C_MESSAGE_CREATE` | 用户与机器人单聊；通常需要先添加机器人或从机器人资料页发起会话 | 已支持 |
| QQ 频道 | `AT_MESSAGE_CREATE` 等 Guild 事件 | 机器人加入频道、订阅 Guild intents | 未实现 |
| 主动/定时推送 | 非入站事件 | 需要用户授权主动消息，并受频率与每日上限限制 | 未实现 |
| 按钮/菜单交互 | `INTERACTION_CREATE` | 用户点击机器人消息按钮或快捷菜单 | 未实现 |
| 入群/退群通知 | `GROUP_ADD_ROBOT` 等 | 机器人被拉入/移出群 | 未处理 |

### 1.2 容易误判的“没有反应”

- **普通群消息不会触发**：默认只有 @ 机器人才会收到 `GROUP_AT_MESSAGE_CREATE`。
- **沙箱实例收不到正式群事件**：沙箱环境只推送测试群事件。
- **机器人不在群里**：平台不会推送该群事件。
- **@全体成员不算 @ 机器人**：必须 @ 机器人本体。
- **同一 AppID 同时跑多个实例**：多个网关连接可能互相顶替，只保留一个实例运行。
- **实例未连接**：刚启动、token 失败、网关断开时不会收到事件。
- **媒体消息内容可能为空**：图片、语音等消息的 `content` 可能为空，但事件仍会到达。
- **正式环境需要审核/发布**：未上线或被限制的功能不会在正式群生效。

## 2. 当前实现的消息日志

适配器现在会记录三类日志：

- `收到群聊消息（群 xxx / 成员 xxx，消息 xxx）：内容`
- `已发送群聊消息（群 xxx，回执 xxx）：内容`
- `收到暂未处理的 QQ 事件：事件名`

日志页新增“只看消息”筛选，收发消息分别用蓝色和绿色显示。若 @ 机器人后仍没有任何 `收到` 日志，说明事件没有到达应用，应检查上面的场景条件，而不是插件逻辑。

## 3. 使用场景分析

| 场景 | 典型触发 | 关键要求 | 当前阶段 |
| --- | --- | --- | --- |
| 群内 AI 问答/陪聊 | 群内 @ 机器人 | LLM API、上下文记忆、人设、超时控制 | 第二阶段 AI 插件 |
| 私聊 AI 助手 | 用户单聊 | 用户可发起单聊、上下文隔离 | 第二阶段 |
| 群管理/FAQ 客服 | @ 或全量消息 | 全量消息需群主授权；管理动作需权限；主动提醒受限 | 后续插件 |
| 通知/订阅推送 | 被动回复或主动消息 | 主动消息需要授权与额度，不能作为默认通道 | 后续 |
| 娱乐互动/小游戏 | @ 机器人或命令 | 命令解析、状态存储、防刷 | 插件化扩展 |
| 查询工具 | @ 机器人 | Function Calling、外部 API、超时与降级 | 后续 |
| 多机器人运营 | 每实例独立 AppID | 实例隔离、独立配置与日志 | 已支持 |
| 频道社区运营 | 频道内 @ | Guild intents、频道权限、独立事件模型 | 未实现 |

### 3.1 平台约束

- 被动回复窗口：群聊 5 分钟内最多 5 次，单聊 60 分钟内最多 4 次。
- 主动消息：依赖用户开启“允许主动发送”，并有 Bot 维度、关系维度和每日上限。
- 群聊默认只能收到 @ 消息；全量消息需要群主设置。
- 单聊通常需要用户先建立与机器人的会话关系。
- 富媒体发送需要先上传获取 `file_info`，不能直接发外链图片。
- 正式环境需要平台审核；沙箱只用于测试群验证。

## 4. 排障顺序

1. 看概览：实例是否 `running`、是否“已连接”。
2. 看日志是否有“QQ 网关已就绪”。
3. 确认当前实例是沙箱还是正式，以及消息来自哪个环境。
4. 确认只有一个使用该 AppID 的实例在运行。
5. 确认消息是直接 @ 机器人，而不是普通群消息。
6. 确认机器人在目标群/测试群中。
7. 看日志是否出现任意“收到暂未处理的 QQ 事件”：有事件说明网关正常，问题在事件类型或场景权限；完全没有事件说明平台没有推送。
8. 正式环境确认机器人已发布、功能已审核通过。
